# FlowTrim Mobile

Android companion app for [FlowTrim](https://github.com/Andermc10/FlowTrim-frontend), the transparent
personal-finance engine. Built with **React Native + Expo + TypeScript**, it consumes the existing
[FlowTrim API](https://github.com/Andermc10/FlowTrim-backend) without any backend change.

> **Status:** HU-81 foundation (tabs, theme, languages, configuration, CI), HU-82 typed API client, HU-83 native
> sign-in, HU-84 settings and app lock, and HU-85 Today. Screens arrive story by story;
> see the epic spec [`EP-17-flowtrim-mobile.md`](https://github.com/Andermc10/FlowTrim-tracker/blob/main/specs/EP-17-flowtrim-mobile.md).

## What it will do (and what it won't)

| On the phone                                                              | Stays on the web                                               |
| ------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Today: safe to spend per currency, committed charges, budgets to watch    | CSV imports and exports, reports, analytics charts             |
| Quick add of expenses, income and transfers                               | Cancellation simulator, cost per use                           |
| Movements of the month                                                    | AI Assistant                                                   |
| Recurring payments with _mark as paid_                                    | Creating / editing recurring payments, accounts and categories |
| Budgets and savings goals (contributions)                                 |                                                                |
| Biometric app lock, opt-in **local** payment reminders, read-only offline |                                                                |

Every figure comes from the API: the app never recalculates money. Expected charges are always labelled _expected_.

## Stack

| Concern    | Choice                                                        | Why                                                       |
| ---------- | ------------------------------------------------------------- | --------------------------------------------------------- |
| Framework  | Expo SDK 58 (managed) + React Native 0.88 + TypeScript strict | Android builds without Android Studio; one codebase       |
| Navigation | Expo Router (file-based, typed routes)                        | Routes are files in `src/app/`                            |
| Tests      | Jest (`jest-expo`) + React Native Testing Library             | Behaviour-level tests, same discipline as the other repos |
| Quality    | ESLint (`eslint-config-expo`) + Prettier, zero warnings       | Enforced in CI                                            |
| API client | `openapi-fetch` + types generated by `openapi-typescript`     | Typed from the real API contract, no hand-copied DTOs     |
| Data       | TanStack Query                                                | Cache, retries (network/5xx only), no retried writes      |

All dependency versions are pinned exactly.

## Project structure

```
src/
  app/                 routes only (Expo Router): every file is a screen or a layout
    _layout.tsx        providers (safe area, theme, i18n) and the root stack
    (tabs)/            Today · Movements · Payments · Plan
  core/                cross-cutting code: api, config, i18n, theme (later: auth, storage, notifications)
  shared/ui/           reusable UI primitives
  features/<feature>/  screens, hooks and components per feature (from HU-85)
  __tests__/           tests that render the real router (tests never live in src/app)
```

## Getting started

Requirements: Node **22.13+**, an Android phone (or emulator) and, for the API, the local
[FlowTrim backend](https://github.com/Andermc10/FlowTrim-backend).

```bash
npm ci
cp .env.example .env   # fill in the public values (see the file)
npm test               # unit tests
npm start              # Metro dev server
```

Native sign-in (HU-83) needs a **development build** (`npm run android` or an EAS development build); Expo Go is not
enough for it.

| Script              | Purpose                                       |
| ------------------- | --------------------------------------------- |
| `npm run lint`      | ESLint + Prettier check, fails on any warning |
| `npm run typecheck` | `tsc --noEmit`                                |
| `npm test`          | Jest                                          |
| `npm run format`    | Prettier write                                |
| `npm run api:sync`  | Download the contract from the local API      |
| `npm run api:types` | Regenerate `src/core/api/schema.d.ts`         |

## API contract

`api/openapi.json` is a committed snapshot of the backend's OpenAPI document; `src/core/api/schema.d.ts` is generated
from it and never edited by hand (CI fails if they drift). To pick up a backend change: run the API with the `http`
profile, then `npm run api:sync && npm run api:types`, and commit both files.

- `.NET decimal` amounts arrive as JSON numbers and are typed as `number`. **The app never does arithmetic with
  money** (JavaScript numbers are binary floats): every figure is computed by the backend and only formatted here.
- Every request goes through one client that adds the bearer token and `Accept-Language`. Failures become a typed
  `ApiError` (`validation`, `badRequest`, `unauthorized`, `forbidden`, `notFound`, `conflict`, `rateLimited`,
  `server`, `network`); unexpected failures show a support **reference** (correlation id), never raw bodies.

## Configuration

Only **public** values, read at build time from `EXPO_PUBLIC_*` variables (`.env`, ignored by Git):
`EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_AUTH0_DOMAIN`, `EXPO_PUBLIC_AUTH0_CLIENT_ID`, `EXPO_PUBLIC_AUTH0_AUDIENCE`.
Release builds refuse a non-`https` API URL and URLs with credentials; error messages name the variable, never its value.

## Security and privacy

The checklist is **OWASP MASVS v2** (spec EP-17 §13). Already in place in HU-81:

- Android auto-backup disabled (`allowBackup: false`) so cached data never leaves the device.
- `https` required outside development; no credentials in URLs.
- `no-console` lint rule: nothing can write financial data to the device log.
- Exact dependency versions, `npm audit` gate for high/critical runtime advisories, Dependabot alerts, secret
  scanning with push protection.
- CI with read-only permissions and no secrets.

Sign-in (HU-83, setup in [`docs/AUTH0-SETUP.md`](docs/AUTH0-SETUP.md)): Authorization Code + PKCE in the system
browser, no client secret, refresh-token rotation; tokens only in `expo-secure-store` (Android Keystore); one refresh
at a time (parallel refreshes would trip Auth0 reuse detection); signing out or a `401` clears the tokens and every
cached query, so nothing of the previous account remains.

App lock and settings (HU-84): optional fingerprint/PIN lock (`expo-local-authentication`, device PIN as fallback)
on cold start and after more than 60 s in the background; the "on" flag lives in SecureStore and is cleared on
sign-out; while the lock is on, `FLAG_SECURE` (`expo-screen-capture`) blanks the recent-apps preview and blocks
screenshots. Permissions the app does not use are removed from the manifest (`READ_EXTERNAL_STORAGE`,
`READ_MEDIA_IMAGES`, `DETECT_SCREEN_CAPTURE`). Language and theme are the only values in AsyncStorage (not
sensitive). Coming with their stories: private notifications.

| Stored where                      | What                                                          |
| --------------------------------- | ------------------------------------------------------------- |
| SecureStore (Android Keystore)    | session tokens, account e-mail, lock on/off                   |
| AsyncStorage                      | language and theme preferences                                |
| Memory only (cleared on sign-out) | API data cache (persisted read-only cache arrives with HU-90) |
